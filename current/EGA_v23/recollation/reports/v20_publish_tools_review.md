## 审查结论

第二十版的两个 Python 脚本相对于第十九版，未发现版号迁移引入的历史覆盖、清单自引用、路径或 ZIP 校验问题。目标目录、快照目录、基线提交、十项发布元数据和八项成品名称均相互一致。实际只读语法检查和隔离临时样例检查均得到预期结果。

**当前模板仍不能按其中的数值直接发布。** 六项 overlay 固定值全部保留第十九版实测数值，必须在第二十版完整冻结并重新生成 ZIP、分片后整组替换。不能只更换 SHA-256。模板首行声称这些值已经是本版实测值，在完成该替换以前也不应被当作实际核验记录。

此外，工作流核验的是八项成品输出；它没有删除上传 overlay 所用的分片。因此，“八项成品全部核验”不等于“Release 总共恰好八个附件”。

## 4. 旧历史与覆盖保护

更新器只允许 ZIP 成员位于新正文、新快照、新工具，或四项根文件 `README.md`、`AGENTS.md`、`CONTINUE_HERE.md`、`REPOSITORY_MANIFEST.json`。`current/EGA_v19/`、`archive_20261121/`、旧快照、`dot_updates_20261124/` 以及旧版工具均不在允许更新路径内。

在实际写入分支，程序还要求：

- 指定基线是当前提交的祖先；相对基线的已提交路径差异恰为本版工作流；工作区干净。
- 新清单不得漏掉旧清单任何 payload 记录。
- 除指定根文件外，旧记录的路径、大小、哈希记录须逐项保持相同。
- 所有 ZIP payload 和未随 ZIP 提供的既有文件先完成大小及 SHA-256 核验，再开始写入。
- 非根文件若已经存在便拒绝覆盖；目标或祖先目录为符号链接时拒绝写入。
- 同一 overlay 重跑走验证分支，检查已应用文件和清单，不再次覆盖。

这意味着远程部署前只应在基线之后单独提交本版工作流；若预先把新工具、正文或其他变更也提交到该分支，严格路径差异检查会拒绝执行。该条件是当前脚本明确规定的部署顺序，不是本次新增要求。

本次没有执行实际写入分支；其基线和旧清单保护通过源码审查确认。隔离样例只调用 `--verify-only`，该选项自身也明确把范围限制为 overlay 与重建清单字节核验，不能把它的成功单独当作实际写入分支全部前置检查已通过。

## 5. 清单、自引用与 ZIP/路径规则

更新器拒绝 `REPOSITORY_MANIFEST.json` 出现在自身 `files` 中；打包器也拒绝这一自引用。在完整 ZIP 中，清单作为额外文件加入一次，不要求清单内部保存自己的哈希。`PACKAGE_VERIFICATION.json` 保存清单和其他成品的哈希；`SHA256SUMS.txt` 在最后生成，包含另外七项文件，排除自身，避免自引用。

两份脚本的路径规范化规则相同：拒绝绝对路径、`..`、反斜杠、重复分隔或 `.` 路径规范化差异，以及任意大小写的 `.git` 路径段。ZIP 成员还须无重名、非目录，类型只能是普通文件或未指定 Unix 类型的普通成员。文件数量和解压总字节必须与固定值一致。打包器对源文件进一步检查符号链接、祖先符号链接和解析后的根目录边界。

打包器以独占创建模式打开 ZIP，对全部成员重新核对路径集合、CRC、解压大小及 SHA-256；不是只检查 ZIP 成功关闭。完整包由清单中所有历史 payload 加清单文件及十项元数据组成，未按“仅本版”过滤掉旧历史。项目包仅截取 `current/EGA_v20/`，在 ZIP 内改为 `EGA_v20/` 前缀。

样例只验证控制流和接口，不证明冻结后的真实大 ZIP、远端工作流、全部历史文件或发布已经通过。本记录完成后，仍须由主流程用最终归档字节执行全量校验并另记结果。
