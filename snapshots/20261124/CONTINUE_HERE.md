## 推荐的接续步骤

1. 按根 README 用 `python3 tools/verify_repository.py --strict` 核验本次公开快照全部文件载荷（Python 3.11 或更新版本），再核对旧包自身清单、新增 Dot 索引与原 ZIP。先确认文件真实存在、源码可读取，以及其来源页和批次关系。
2. 检查 `main.tex`、`report.tex` 的实际输入链及末段，确认原有合订本仍与其状态文件相符。归档完成不等于新批次已进入输入链。
3. 若任务是整合，把第 69—87 批的后续及补遗与第 88—108 批的回校分别映射到原著位置。对重叠段逐段比较；确证修订写入相应位置，并保留原稿、英译编者、原批译者与本次整合的来源记录。不要按 69—108 的包序把重复正文全部追加到书末。
4. 复核未决事项的状态。旧“未收入”可能已由后续批次接上；数学疑点则须有独立证据才能消除。新增批次中标明的未辨边注、草稿缺文、反例和补加条件，应继续可见。
5. 在工作副本中编辑，不改写原始归档。实际整合或续译后更新模块源码、独立 TeX、状态和差异记录，按构建入口运行 XeLaTeX，检查日志并实际查看页面；只把真实运行结果写进新报告。
6. 新交付应分别列出“已合入 PDF 的范围”“仍为独立档案的范围”“本次校勘范围”“下一原文页／条目”。保留原书末资料、索引、目录、参考文献、勘误增补等的真实状态；未检查的部分不以猜测填满。
